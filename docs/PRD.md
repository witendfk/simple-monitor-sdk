## 1. 项目背景与定位

**自研采集层的完整前端监控产品**（Real User Monitoring）：SDK（错误 + 性能 + 行为 + 可靠传输 + 合规）+ 服务端平台（接入 / 存储 / 聚合 / 看板 / 告警 / SourceMap 符号化 / AI 诊断）。专注 Web 应用，通过自动采集与聚合分析，实时掌握真实用户体验、快速定位线上问题。

差异化定位：采集层全部自研（不依赖 Sentry/web-vitals 官方库，以官方库为一致性 oracle），本地零依赖即可起步（Memory 双形态），传输可靠性与隐私合规为一等需求。

演进三档（当前聚焦 Web 的 A 档；对外使用指南待功能与发布流程稳定后补）：

| 档位            | 标准                                                                                                             | 状态                                           |
| --------------- | ---------------------------------------------------------------------------------------------------------------- | ---------------------------------------------- |
| A. Web 核心产品 | Web 采集、接入、错误定位、看板与告警闭环；权限分离、隐私闭环和关键数据准确性验收完成。AI、小程序及候选池不阻塞 A | 开发中，验收项见 [CURRENT](./tasks/CURRENT.md) |
| B. 可开源项目   | A + 真实 npm 发布 + 面向使用者的接入指南 + 陌生人 15 分钟接入成功                                                | npm 发布搁置中；接入指南待产品落地后补         |
| C. 生产级 SaaS  | 多租户隔离 / SLA / 海量成本优化                                                                                  | 不做，纳入演进叙事                             |

## 2. 产品形态与范围

**SDK 包矩阵**（pnpm monorepo，十包单向依赖）：

| 包                                              | 职责                                                                                  |
| ----------------------------------------------- | ------------------------------------------------------------------------------------- |
| `@simple-monitor/protocol`                      | 协议 v1 单一事实来源：zod schema + LIMITS 截断常量，SDK 与服务端共用                  |
| `@simple-monitor/types`                         | 公共类型定义                                                                          |
| `@simple-monitor/shared`                        | 共享常量与默认配置（规划并入 protocol）                                               |
| `@simple-monitor/utils`                         | 基础设施：AOP 替换、微任务队列、脱敏 mask、堆栈解析                                   |
| `@simple-monitor/core`                          | 引擎：MonitorClient 类、事件总线、面包屑、信封组装、采样、批量传输、IndexedDB 缓存    |
| `@simple-monitor/browser`                       | 唯一 instrumentation 层：xhr/fetch/history/console 补丁、错误捕获、行为采集、白屏检测 |
| `@simple-monitor/web-performance`               | 纯性能计算引擎：自研 Web Vitals + NT/RT/FPS/LongTask                                  |
| `@simple-monitor/web`                           | 门面：一个 init 全量接入（主入口零框架依赖）                                          |
| `@simple-monitor/vue` / `@simple-monitor/react` | 框架适配（errorHandler / ErrorBoundary + 组件名解析）                                 |

**服务端**：`apps/server`（NestJS 接入/存储/聚合/查询/告警）+ `apps/dashboard`（React + ECharts 自建看板）+ `examples/demo-app`（真实业务形态接入示例，订单管理台）。

**部署双形态**（DIP 三接口双实现）：Memory 形态（零依赖本地起步、全链路 e2e）/ 基础设施形态（当前 Redis Stream + ClickHouse；Postgres 属 M7.5 目标）。

## 3. 核心功能需求 — SDK 采集域

### 3.1 性能监控

**目标**：全方位监控页面加载性能，量化用户体验，指标语义与业界标准对齐且有机制保证。

| 功能项                             | 说明                                                                                                             | 状态                        |

| **Core Web Vitals 自研实现**       | FP/FCP/LCP/CLS/INP，含 attribution 上下文；CLS session-window、INP interactionId 聚合（≤50 取最大 / >50 取 P98） | ✅                          |
| **一致性保证（oracle）**           | 自研指标与官方 web-vitals 库同页双跑，偏差断言（LCP ±50ms / CLS ±0.02）进 CI conformance job                     | ✅                          |
| **页面加载阶段**                   | NT（导航各阶段耗时）/ RT（资源分阶段）；TAO 缺失等无法归一场景返回 null，不造假数                                | ✅                          |
| **首屏时间（CCP）**                | 监听页面打开后时间窗口内 DOM 变化，计算首屏渲染完成时间                                                          | ✅                          |
| **卡顿监控**                       | LongTask 采集：count/total/worst + Top-N 归因 + 三档分布（50-100/100-200/≥200ms）                                | ✅（分档 M7）               |
| **FPS 采样**                       | 页面帧率监控                                                                                                     | ✅                          |
| **SPA 支持**                       | 路由级 viewId 贯穿，性能与错误信封可关联路由页                                                                   | ✅                          |
| **软导航 vitals / Element Timing** | bfcache/软导航指标重算；Element Timing API                                                                       | ✂️ 裁剪线（时间不够按序砍） |

### 3.2 异常监控

**目标**：自动捕获前端运行时各类错误，提供完整上下文（符号化堆栈 + 行为轨迹），支撑快速定位修复。

| 功能项                 | 说明                                                                                                                        | 状态                          |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------- | ----------------------------- |
| **JS 运行时错误**      | 全局捕获 Error/TypeError/ReferenceError 等                                                                                  | ✅                            |
| **Promise 未处理拒绝** | unhandledrejection 事件捕获                                                                                                 | ✅                            |
| **静态资源加载错误**   | script/style/image/media 失败；拆 resource_kind（script/image/css/media/other）                                             | ✅（分类 2026-10-09）         |
| **HTTP 请求异常**      | 4xx/5xx/网络错误，附 method/url/status/elapsedTime/traceId；响应体安全采样（2048 截断 + 脱敏）                              | ✅                            |
| **框架错误**           | Vue errorHandler / React ErrorBoundary，组件名解析（React 18 兼容）                                                         | ✅                            |
| **白屏检测**           | load 后 16 点视口采样（elementsFromPoint），命中全空判定白屏 → 独立错误事件                                                 | ✅                            |
| **指纹与去重**         | SDK 侧 message 级 errorId 流量去重；服务端 fingerprint（type+message+堆栈首帧 url:line:col）分组，流量粗/分析细             | ✅                            |
| **错误分组与发版回归** | 服务端按 fingerprint 聚合 count/firstSeen/lastSeen、记录 releases；按 release 过滤与 isNewInRelease 徽标尚未在查询 API 生效 | ✅ 分组；🚧 M8 发版过滤与徽标 |
| **SourceMap 符号化**   | 构建后 CLI 上传（release+URL 精确/后缀匹配），错误堆栈还原为源码位置                                                        | ✅                            |
| **手动上报 API**       | captureException / captureMessage                                                                                           | 🚧（DoD 未落地，里程碑待排）  |
| **错误过滤标准项**     | ignoreErrors / allowUrls / denyUrls                                                                                         | 🚧（同上）                    |

### 3.3 API 监控

| 功能项                     | 说明                                                                                                                                     | 状态                        |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- | --------------------------- |
| **请求自动拦截**           | XHR/fetch 统一包装，全项目唯一 instrumentation 层；SDK 自身传输请求防自循环                                                              | ✅                          |

### 3.8 可靠传输（核心差异域）

**目标**：降低异常场景下的数据丢失与重复；明确每一段可确认的边界和有界丢弃条件。

| 功能项             | 说明                                                                                                                                     | 状态                                                           |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| **批量信封**       | 5s / 10 条 flush；协议 v1 信封（protocolVersion/sentAt/auth/session/context/events）                                                     | ✅                                                             |
| **gzip 压缩**      | CompressionStream + 降级；服务端需同时限制压缩输入与解压输出                                                                             | ✅ 压缩链路与输入上限；🚧 解压上限                             |
| **通道状态机**     | active/leaving 显式状态；错误/性能/行为/API 离场发送，>64KB 的 beacon 按 UTF-8 字节拆批且事件恰好进入一个分片                            | ✅ 主通道切换；🚧 行为通道与拆批正确性                         |
| **失败重试**       | 指数退避，429/503 遵从 Retry-After，4xx 不重试直接弃                                                                                     | ✅                                                             |
| **离线重放**       | IndexedDB 缓存，HTTP 2xx 后删除；上限 50 条丢最老 / 3 天过期；online 事件即时重放。sendBeacon 仅能确认浏览器接受排队，不能确认服务端接收 | ✅（有界尽力送达）                                             |
| **采样率**         | sampleRate 采集层过滤（省流量也省内存）                                                                                                  | ✅                                                             |
| **Image 兜底通道** | 图片请求上报                                                                                                                             | ✂️ 放弃（204 对 Image 只触发 onerror，送达不可确认引入假成功） |

## 7. 范围外与候选池

**✂️ 明确不做**（有决策记录，反复评估不翻案）：

- 可视化圈选埋点（ADR-8：选择器管理 + DOM 脆弱性成本远超收益）
- 地域/IP 归属（不引 GeoIP 依赖）
- Image 兜底上报通道（假成功风险）
- Taro、uniapp H5 编译目标、支付宝/抖音等直出独立适配（小程序支持两步走见 §3.10）
- Flutter 多平台（残留已清理）
- 生产级 SaaS（多租户隔离/SLA，C 档仅纳入演进叙事）
- destroy 后同页重建（声明边界：重置请刷新页面；iframe/微前端多实例不受限）

**候选演进池**（未纳入本期承诺；圈定优先级后修订本 PRD 再立项）：

- 通知渠道 provider 抽象（钉钉/企微/Slack/邮件，webhook 之外）
- HLL 影响用户估算（HyperLogLog 按 fingerprint）
- metric_minute 分钟预聚合
- SSE 实时推送
- AI 演进线（按序解锁）：仓库只读上下文 → 自动修复 PR（沙箱+人工确认）→ 告警联动自动诊断 → 流式输出
