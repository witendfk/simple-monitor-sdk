# 存储与服务分层架构（生产级设计）

> 状态：**设计稿，待确认后实施**。本文是总纲 ADR-4（Postgres 元数据 + ClickHouse 事件）的落地级设计，替代 M4 时期的「单宽表 + 全内存」过渡形态。
> 定位声明：架构按生产级设计（分表 / TTL / 分区 / 幂等 / 状态机），功能交付可以按里程碑逐步完备——但结构与接口从第一天就是终局形态，不再有「demo 表」。

---

## 一、总体分层

```
SDK（采集）
   │  POST /report/batch（gzip / beacon，协议 v1 信封）
   ▼
Gateway 层（apps/server/src/gateway）
   ├─ 鉴权：projects.public_key 校验 → 服务端覆写 project_id（防客户端篡改）
   ├─ 幂等：Redis SETNX dedup:{project_id}:{event_id}（24h TTL，对齐 SDK 重试窗口）
   ├─ 限流：Redis 令牌桶（Lua 原子，per-project capacity + refill）
   └─ 入队：BullMQ/Redis Stream（error/perf 独立队列；sync/queue 双写模式开关）
   ▼
Processor 层（消费，per-domain）
   ├─ ErrorProcessor：sourcemap 符号化 → 指纹归一化 → Issue UPSERT → 写 CH error_events
   ├─ PerfProcessor：metric_minute 分钟分位 UPSERT → 写 CH perf_events
   ├─ BehaviorProcessor / ApiProcessor：白名单归一 → 写 CH 分表
   └─ 失败：重试耗尽 → dead_letter 表
   ▼
存储层（双库）
   ├─ ClickHouse：事件明细（按 kind 分表，分区/TTL/物化视图）——只增不改的时序事实
   └─ Postgres：元数据与状态（projects/users/issues/alert_rules/releases/sourcemaps）——可变状态
   ▼
Query 层（5 域 service：overview / errors / performance / visits / api）
   └─ 看板 BFF：overview（健康度+5 域 allSettled）/ errors / performance / visits / api / settings
```

**职责铁律**：ClickHouse 只存「 append-only 的事件事实」，一切可变状态（Issue 状态、告警规则、项目配置）在 Postgres；查询层不写库；Gateway 不碰存储细节。

## 二、ClickHouse：事件域（按 kind 分表，替代单宽表）

设计原则：每类事件一张表（列即该类事件的完整形状，不再「列存 unwind + 万能 String 列」）；月分区；TTL 统一 90 天；ORDER BY 服务各自最高频查询；聚合全部走物化视图（查询永远不打明细大表）。

### 2.1 error_events（错误明细）

```sql
CREATE TABLE error_events
(
  ts               DateTime          COMMENT '客户端发生时间',
  received_at      DateTime DEFAULT now(),
  project_id       LowCardinality(String),
  release          LowCardinality(String),
  env              LowCardinality(String),
  session_id       String,
  tracker_id       String,
  view_id          String,
  page             String,
  -- 错误本体
  error_type       Enum8('js'=1,'promise'=2,'resource'=3,'http'=4,'white_screen'=5,
                         'vue'=6,'react'=7,'log'=8,'unknown'=9)  COMMENT '9 分类（M7 9 分类对齐）',
  resource_kind    Enum8('script'=1,'image'=2,'css'=3,'media'=4,'other'=5) COMMENT '仅 resource 类非空',
  message          String            COMMENT '原始消息',
  message_head     String            COMMENT '归一化消息前 128 字符（指纹分组键冗余列）',
  fingerprint      FixedString(40)   COMMENT 'sha1(subType|归一化message|topFrame|func)',
  error_id         Int64             COMMENT 'SDK 流量去重 id',
  component_name   String,
  stack_frames     String            COMMENT 'JSON Array<Frame>',
  -- HTTP 上下文（http 类专属）
  http_method      LowCardinality(String),
  http_url         String,
  http_status      UInt16,
  http_duration_ms UInt32,
  -- 行为现场
  breadcrumbs      String            COMMENT 'JSON Array（已脱敏截断）',
  -- 维度
  browser          LowCardinality(String),
  os               LowCardinality(String),
  device_type      LowCardinality(String),
  country          LowCardinality(String) COMMENT 'GeoIP（预留）'
)
ENGINE = MergeTree
PARTITION BY toYYYYMM(ts)
ORDER BY (project_id, error_type, fingerprint, ts)
TTL toDateTime(ts) + INTERVAL 90 DAY
SETTINGS index_granularity = 8192;

-- 查询加速：按版本过滤（发版对比页）
ALTER TABLE error_events ADD INDEX idx_release release TYPE set(0, 64) GRANULARITY 2;
```

### 2.2 perf_events（性能指标，一行一指标）

```sql
CREATE TABLE perf_events
(
  ts           DateTime,
  project_id   LowCardinality(String),
  release      LowCardinality(String),
  env          LowCardinality(String),
  session_id   String,
  view_id      String,
  page         String,
  metric       LowCardinality(String) COMMENT 'LCP/INP/CLS/FCP/TTFB/fps/long-task/…',
  value        Float32,
  score        Float32,
  detail       String COMMENT 'JSON（NT 阶段/INP 明细/慢资源 Top 等）',
  browser      LowCardinality(String),
  os           LowCardinality(String),
  device_type  LowCardinality(String)
)
ENGINE = MergeTree
PARTITION BY toYYYYMM(ts)
ORDER BY (project_id, metric, ts)
TTL toDateTime(ts) + INTERVAL 90 DAY;

-- 小时级分位物化视图：性能页与发版对比直接读本表（quantileTDigestState 合并态）
CREATE MATERIALIZED VIEW perf_stats_mv TO perf_stats
AS SELECT
  project_id, metric, release,
  toStartOfHour(ts) AS hour_bucket,
  count() AS n,
  quantileTDigestState(0.50)(value) AS p50,
  quantileTDigestState(0.75)(value) AS p75,
  quantileTDigestState(0.95)(value) AS p95
FROM perf_events GROUP BY project_id, metric, release, hour_bucket;

CREATE TABLE perf_stats
(
  project_id  LowCardinality(String),
  metric      LowCardinality(String),
  release     LowCardinality(String),
  hour_bucket DateTime,
  n           UInt64,
  p50 AggregateFunction(quantileTDigest(0.50), Float32),
  p75 AggregateFunction(quantileTDigest(0.75), Float32),
  p95 AggregateFunction(quantileTDigest(0.95), Float32)
) ENGINE = AggregatingMergeTree ORDER BY (project_id, metric, release, hour_bucket);
```

### 2.3 behavior_events（行为域：PV / 停留 / 曝光 / 埋点）

```sql
CREATE TABLE behavior_events
(
  ts            DateTime,
  project_id    LowCardinality(String),
  release       LowCardinality(String),
  session_id    String,
  tracker_id    String,
  view_id       String,
  page          String,
  behavior_type Enum8('page_view'=1,'page_dwell'=2,'expose'=3,'track'=4),
  -- page_view
  url           String,
  load_type     Enum8('navigate'=1,'reload'=2,'back_forward'=3),
  referrer_host LowCardinality(String) COMMENT '来源归因（M8 visits 前置）',
  utm_source    LowCardinality(String),
  utm_medium    LowCardinality(String),
  utm_campaign  LowCardinality(String),
  -- dwell
  active_ms     UInt32,
  -- expose / track
  name          String  COMMENT '埋点名（≤128）',
  props         String  COMMENT 'JSON（≤2KB）',
  duration_ms   UInt32,
  -- 维度
  browser       LowCardinality(String),
  os            LowCardinality(String),
  device_type   LowCardinality(String)
)
ENGINE = MergeTree
PARTITION BY toYYYYMM(ts)
ORDER BY (project_id, behavior_type, ts)
TTL toDateTime(ts) + INTERVAL 90 DAY;

-- PV/UV 小时物化视图（visits 页直接读）
CREATE MATERIALIZED VIEW pv_stats_mv TO pv_stats
AS SELECT
  project_id,
  toStartOfHour(ts) AS hour_bucket,
  count() AS pv,
  uniqState(session_id) AS uv_states
FROM behavior_events
WHERE behavior_type = 'page_view'
GROUP BY project_id, hour_bucket;

CREATE TABLE pv_stats
(
  project_id LowCardinality(String),
  hour_bucket DateTime,
  pv UInt64,
  uv_states AggregateFunction(uniq, String)
) ENGINE = AggregatingMergeTree ORDER BY (project_id, hour_bucket);
```

### 2.4 api_events（成功请求明细，M7 kind api）

```sql
CREATE TABLE api_events
(
  ts          DateTime,
  project_id  LowCardinality(String),
  session_id  String,
  view_id     String,
  page        String,
  method      LowCardinality(String),
  url         String,
  status      UInt16,
  duration_ms UInt32,
  is_slow     UInt8,
  trace_id    String,
  browser     LowCardinality(String),
  os          LowCardinality(String)
)
ENGINE = MergeTree
PARTITION BY toYYYYMM(ts)
ORDER BY (project_id, url, ts)
TTL toDateTime(ts) + INTERVAL 30 DAY;

-- API 监控物化视图：吞吐 / p75 时延 / 错误率
CREATE MATERIALIZED VIEW api_stats_mv TO api_stats
AS SELECT
  project_id, url,
  toStartOfHour(ts) AS hour_bucket,
  count() AS requests,
  quantileTDigest(0.75)(duration_ms) AS p75_duration,
  countIf(status >= 400) AS errors
FROM api_events GROUP BY project_id, url, hour_bucket;

CREATE TABLE api_stats
(
  project_id LowCardinality(String),
  url String,
  hour_bucket DateTime,
  requests UInt64,
  p75_duration Float32,
  errors UInt64
) ENGINE = SummingMergeTree ORDER BY (project_id, url, hour_bucket);
```

## 三、PostgreSQL：元数据与状态域（21 表的精简生产集）

```sql
-- ============ 多租户与权限（§3.8 分离设计的数据地基） ============
CREATE TABLE users (
  id            varchar(32) PRIMARY KEY,
  email         varchar(255) NOT NULL UNIQUE,
  password_hash varchar(255) NOT NULL,
  display_name  varchar(64),
  role          varchar(16) NOT NULL DEFAULT 'member',   -- owner / admin / member
  created_at    timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE projects (
  id                varchar(32) PRIMARY KEY,
  slug              varchar(64) NOT NULL UNIQUE,
  name              varchar(128) NOT NULL,
  public_key        varchar(64) NOT NULL UNIQUE,         -- SDK 上报身份（可公开）
  secret_key_hash   varchar(255) NOT NULL,               -- 管理身份（bcrypt）
  rate_limit_per_min integer NOT NULL DEFAULT 1000,
  is_active         boolean NOT NULL DEFAULT true,
  created_at        timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE project_members (
  project_id varchar(32) REFERENCES projects(id),
  user_id    varchar(32) REFERENCES users(id),
  role       varchar(16) NOT NULL DEFAULT 'member',      -- owner / admin / member
  PRIMARY KEY (project_id, user_id)
);

-- ============ 错误 Issue（状态机，退出「查询时聚合」） ============
CREATE TABLE issues (
  id                varchar(32) PRIMARY KEY,
  project_id        varchar(32) NOT NULL REFERENCES projects(id),
  fingerprint       char(40) NOT NULL,                   -- 归一化指纹（sha1 hex）
  title             varchar(200) NOT NULL,
  status            varchar(16) NOT NULL DEFAULT 'open', -- open / resolved / ignored
  first_seen        timestamptz NOT NULL DEFAULT now(),
  last_seen         timestamptz NOT NULL DEFAULT now(),
  event_count       bigint NOT NULL DEFAULT 0,
  affected_sessions integer NOT NULL DEFAULT 0,
  first_release     varchar(64),
  last_release      varchar(64),
  UNIQUE (project_id, fingerprint)
);
CREATE INDEX idx_issues_open ON issues (project_id, status, last_seen DESC);

-- ============ 告警（替换内存 AlertRuleStore） ============
CREATE TABLE alert_rules (
  id               varchar(32) PRIMARY KEY,
  project_id       varchar(32) NOT NULL REFERENCES projects(id),
  type             varchar(16) NOT NULL,                 -- error_spike / perf_threshold
  name             varchar(100) NOT NULL,
  webhook_url      text NOT NULL,
  cooldown_minutes integer NOT NULL DEFAULT 15,
  enabled          boolean NOT NULL DEFAULT true,
  config           jsonb NOT NULL,
  created_at       timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE alert_history (
  id         varchar(32) PRIMARY KEY,
  rule_id    varchar(32) NOT NULL REFERENCES alert_rules(id) ON DELETE CASCADE,
  fired_at   timestamptz NOT NULL DEFAULT now(),
  message    text NOT NULL,
  context    jsonb
);
CREATE INDEX idx_alert_history_rule ON alert_history (rule_id, fired_at DESC);

-- ============ 发版与 SourceMap（替换内存 SourcemapService） ============
CREATE TABLE releases (
  id         varchar(32) PRIMARY KEY,
  project_id varchar(32) NOT NULL REFERENCES projects(id),
  version    varchar(64) NOT NULL,
  created_at timestamptz NOT NULL DEFAULT now(),
  UNIQUE (project_id, version)
);

CREATE TABLE sourcemap_artifacts (
  id         varchar(32) PRIMARY KEY,
  project_id varchar(32) NOT NULL REFERENCES projects(id),
  release    varchar(64) NOT NULL,
  url        text NOT NULL,
  store_key  text NOT NULL,                            -- 对象存储键（本地盘/S3 抽象）
  uploaded_at timestamptz NOT NULL DEFAULT now(),
  UNIQUE (project_id, release, url)
);
```

## 四、服务分层与模块边界（apps/server 重构目标形态）

```
src/
├── gateway/        # 接收：鉴权（public_key）→ 幂等（SETNX）→ 限流（令牌桶）→ 分流入队
├── queue/          # BullMQ 或 Redis Stream 双实现（sync/queue 模式开关保留）
├── processors/     # error / perf / behavior / api 消费者（符号化→指纹→Issue UPSERT→写 CH）
├── storage/
│   ├── clickhouse/ # 每事件域一个 repository（error/perf/behavior/api + stats 查询）
│   └── postgres/   # projects / issues / alert_rules / releases / sourcemap repositories
├── query/          # 5 域只读 service（overview / errors / performance / visits / api）
├── alert/          # 评估引擎（读 PG 规则 + CH 指标）+ 通知渠道 provider 抽象
├── realtime/       # SSE（Redis pub/sub）
└── settings/       # sourcemap 上传（secret_key 鉴权 + 存储抽象）
```

**接口不破坏零依赖起步**：`IProjectStore / IIssueStore / IAlertRuleStore / IEventQueue / IEventStorage(分表)` 全部接口化——Memory 实现保留（本地零依赖/测试），PG/CH 实现（生产）。`NODE_STORAGE=memory|infra` 一键切换，与现有 DIP 纪律一致。

## 五、实施切分（每批独立可验收）

| 批次 | 内容 | 验收 |
|---|---|---|
| **P1 元数据落地** | PG schema 全量（上第三节）+ drizzle 或 pg repository：projects/issues/alert_rules 替换内存实现；PROJECTS_JSON 兼容为 seed | docker compose 起 PG → Issue 建规则走 PG 持久化 → 重启不丢 |
| **P2 CH 分表** | 单宽表 events → 2.1-2.4 四张分表 + 4 个物化视图；normalize 按 kind 路由分表；单表实现退役 | demo:full 行为/错误/性能各自入对应表；查询 API 不变 |
| **P3 权限分离** | projects 双密钥 + users/members + JWT + RolesGuard；上报走 public_key、管理 API 走 secret_key + JWT | 公开 key 调管理 API → 401（§3.8 验收） |
| **P4 gateway 加固** | SETNX 幂等 + 令牌桶 Lua 限流 + projectId 服务端覆写 | 重放信封 → duplicates 计数；超限 429 + 精确 Retry-After |
| **P5 看板对齐** | 4 分组菜单 + 总览（健康度英雄卡+5 域卡）/异常分析（9 分类+排行+堆叠+维度）/页面性能/API 监控/页面访问 | 按参考页面结构逐页验收 |

依赖 SDK 侧的小前置：资源错误拆 `resource_kind`（9 分类）；UTM 归因采集（M8 visits）。

## 六、明确不做（维持总纲裁剪线）

GeoIP 地域（预留列，不引依赖）→ 多活分布式 → 数据多租户物理隔离（逻辑隔离足够）。
